# Анимации версии 2 — спецификация для переноса

Документ для разработчика: что, как долго и с какой кривой движется в версии 2
(`v2.html`, `data-version="2.3"`, и `match.html`). Всё время — в миллисекундах.
Рядом с каждым блоком — где искать код. В прототипе анимации сделаны на
Web Animations API (`el.animate(...)`) и CSS (`transition` / `@keyframes`);
только матч использует anime.js (`js/match.js`).

Версия 3 (`?app=3`) и старые ветки 2.1 / 2.2 здесь не описаны.

---

## 1. Общие правила

### Кривые (easing)

| Имя | Значение | Где |
|---|---|---|
| **ios** — основная | `cubic-bezier(0.32, 0.72, 0.35, 1)` | шторки, переходы, нажатия, сворачивание карточек |
| **spring** — мягкая пружина | `cubic-bezier(0.34, 1.32, 0.42, 1)` | индикаторы табов, «поп» элементов, тосты, тултип сундука |
| **spring-strong** — сильная пружина | `cubic-bezier(0.34, 1.56, 0.64, 1)` | иконки табов, точки шкалы, галочки |
| **out-expo** | `cubic-bezier(0.22, 1, 0.36, 1)` | заполнение шкалы, искры, появление офферов |
| **ease-out / ease-in-out** | стандартные | короткие «пульсы» и бесконечные покачивания |

### Нажатие (press)

Все нажимаемые элементы при `:active` уменьшаются и возвращаются по **ios**:
кнопки и плитки — `scale(0.97)`, карточки и иконки — `scale(0.94–0.96)`,
стеклянные круглые кнопки 44px — `scale(0.9)`. Длительность 150–180.

### «Пульс» (одноразовый отклик)

Частый приём: элемент коротко увеличивается и возвращается —
`scale(1) → scale(1.12…1.25) → scale(1)`, 240–420, `ease-out` (или **spring**).
Используется, когда в элемент «прилетело» что-то (счётчик, бирка, таб).

### Уменьшение движения

При `prefers-reduced-motion: reduce` бесконечные анимации выключаются
(левитация, свечения, радар), длинные последовательности сокращаются
(паузы — не дольше 300) или заменяются простым затуханием.

### Пропуск

На экране открытия сундука крестик во время анимации **пропускает** её:
все паузы обнуляются, текущие анимации доигрываются мгновенно, сразу
показывается итоговая сетка наград и «Забрать».

## 2. Общие компоненты

### Переход между разделами (нижняя навигация)
`js/v2.js` → `showScreen()`, `css/v2.css`

- Разделы сменяются **кроссфейдом**: новый `opacity 0 → 1`, старый `1 → 0`,
  `0.25s ease` одновременно; через 280 старый скрывается. Горизонтального
  сдвига нет (разделы будут на разных роутах).
- Подсветка активного таба переезжает: `transform` + `width`, 450, **spring**.
- Иконка таба при нажатии — `scale(0.85)`, 200, **spring-strong**.
- Шапка раздела: при прокрутке под ней появляется подложка — `opacity`, 250.

### Сегменты (вкладки внутри раздела: «Ежедневные / Каждую неделю»)
`js/v2.js` → `createChipTabs()`

- Индикатор переезжает: `transform` + `width`, 380, **spring**.
- Новая панель появляется фейдом `opacity 0 → 1`, 250, `ease-out`.
- Высота контейнера подстраивается под новую панель: `height`, 400, **ios**
  (только в момент переключения).

### Шторки (bottom sheet)
`js/sheets.js` → `bottomSheet()`, `css/ny24.css` (`.bs`), `css/v2.css` (`.v2-sheet`)

- Открытие / закрытие: `translateY(105%) ↔ 0`, 450, **ios**
  (старые шторки `.v2-sheet` — 420).
- Затемнение фона: `opacity`, 350 (у `.v2-sheet` — 300).
- Смахивание: шторка едет за пальцем без анимации; отпустили — закрывается,
  если сдвиг > 25% высоты или быстрый жест (> 40px и > 0.6 px/мс), иначе
  возвращается той же анимацией.

### Тултип
`js/tooltip24.js`, `css/tooltip24.css`

- Появление: `opacity 0 → 1` + сдвиг на 4px к элементу (`translateY(∓4px) → 0`),
  200, `ease`. Скрытие — обратно, элемент удаляется через 200.

### Тост сверху (профиль)
`js/profile.js` → `showProfileToast()`, `css/profile24.css`

- Выезжает сверху `translate(-50%, -90px) → 0`, 350, **spring**; висит 1800;
  уезжает обратно.

### Полёт иконки в цель
`js/tasks22.js` → `TASKS22.flyIcon()`, `js/tasks.js` → `flyBolt()`, `burstAt()`

Используется для звёзд, снежинок, билетов, монет.

- **flyIcon** (900, `fill: both`): иконка «выпрыгивает» из источника
  (`scale 0.4 → 1.15` на 22% времени, сдвиг до 25px), затем летит по
  квадратичной кривой Безье с точкой изгиба над серединой пути
  (на 60–120px выше), с **ускорением** (`t²`), уменьшаясь `1.15 → 0.5`.
- **flyBolt** (820) — то же, точка «выпрыгивания» на 24% времени, лёгкий
  поворот ±30°.
- Несколько иконок летят с задержкой 65–90 между ними.
- По прилёту каждой: цель делает **пульс** (240–300) и в точке — **burstAt**:
  кольцо `scale 0.3 → 1.6`, 380, `ease-out` + 6 искр, разлетающихся на
  20–34px, 420, **out-expo**.

### Свернуть / развернуть карточку
`js/tasks.js` → `collapse()` / `expandIn()`

- Свернуть: `height h → 0`, `opacity 1 → 0`, `scale 1 → 0.92`,
  `margin-bottom 16 → 0`, 320, **ios**; потом элемент удаляется.
- Развернуть — обратно, 380, **ios**.

### Заполнение шкалы
`fillProgress()`, `css/tasks.css`

- Ширина, число в бирке и «зажигание» сундуков синхронны (один rAF-цикл),
  900, `easeOutCubic`.
- По полоске пробегает блик (`tasksFillShine`), 900, `ease-out`.
- Когда полоска доходит до сундука, он «просыпается»: пульс
  `scale 1 → 1.35 → 1`, 420, **spring**, и переходит в состояние «готов».

### Сундук «готов»
`css/tasks.css`

- Подпрыгивает: `tchestHop`, цикл 1600, `ease-in-out` (прыжок −6px с наклоном
  в первой половине, затем пауза).
- За ним золотое свечение покачивается и «дышит»: `tchestGlow`, цикл 3000.
- Подсказка «Вам доступен приз» (один раз): через 450 после входа в
  «Задания» появляется `opacity 0 → 1`, `translateY(-6px) scale(0.92) → 0`,
  260, **spring**.

### Открытие сундука-вехи
Тот же экран, что в магазине (раздел 5, «Экран открытия»), **без** монет / ключа
в начале и **без** бонуса. После «Забрать» сундук на шкале меняется на
открытый с пульсом `scale 0.6 → 1.15 → 1`, 420, **spring**.

### Кнопка события в углу «Заданий»
`js/events22.js` → `syncEventFab23()`, `css/v22.css`

- Появляется при входе в «Задания»: `scale 0.4 → 1.08 → 1` + `opacity`, 380, `ease-out`.
- Нажатие: `scale 0.92`, 200.
- Полоска прогресса внутри доезжает: `width`, 700, `cubic-bezier(0.45, 0, 0.25, 1)`.
- Приз на кнопке покачивается: `evFabBob`, цикл 2400.
- Если есть что забрать — кольцо пульсирует жёлтым свечением: `evFabGlow`, цикл 1400.
- Бейдж-счётчик «впрыгивает»: `scale 0 → 1.5 → 1`, 420, задержка 300.

15-лучевая — навстречу ±14°, `scale 1.06 ↔ 0.9` и мерцает (`lbStarB`, цикл 3600).
Эти анимации на самих звёздах, поэтому не конфликтуют с появлением и
разгоранием (они на контейнере `.lb-glow`).

**«Забрать»**: каждая награда остаётся на месте (копия поверх), фон, ячейки и
кнопка гаснут (`opacity`, 300), а награды по очереди (задержка `250 + i × 200`)
приподнимаются (`−14px scale 1.06` на 20%) и летят в цель, уменьшаясь до 24px,
950, `cubic-bezier(0.5, 0, 0.3, 1)`. Цели: монеты и дубль — счётчик монет,
ключи — счётчик ключей, карта — таб «Карты», оформление — таб «Игра»,
бонус — таб «Призы» (вне магазина монеты и ключи летят в таб «Магазин»).
Цель по прилёту — пульс `scale 1.25` с жёлтым `drop-shadow`, 420.

### Переход хода
- Плашка «Ваш ход» / «Ход соперника»: `opacity 0 → 1`, 250, держится 3000, `1 → 0`, 250.
- Карта из колоды в руку: рубашка летит из значка колоды в слот (анимируются
  `left / top / width / height`, не `scale` — иначе тянется узор рубашки),
  900, `cubic-bezier(0.32, 0.72, 0.35, 1)`; затем **переворот**: `scaleX 1 → 0`,
  150, `inQuad` → смена лица → `scaleX 0 → 1`, 150, `outQuad`.
- Таймер хода: кольцо убывает 20 000 линейно; на 40% остатка — жёлтое, на 15% —
  красное (цвет `transition` 300).

### Ход соперника
- Статус «Думает / Перебирает карты / Сравнивает числа» меняется каждые 1300,
  три точки мигают (цикл 1400, сдвиг 200 / 400); думает 3000–6000.
- Рубашка летит из колоды соперника в клетку, 900; пауза 450; переворот 150 + 150;
  дальше захват — как у игрока.

## 13. Как переносить

- **WAAPI → React**: последовательности (`await el.animate(...).finished`) удобно
  оставить императивными — в `useEffect` / обработчике с `ref` на элемент;
  либо на Framer Motion (`animate()` с `await`), кривые и длительности —
  из таблиц выше.
- **CSS** (`transition`, `@keyframes`, бесконечные покачивания) переносится как есть.
- **Синхронные вещи** (шкала + число + «зажигание» сундуков, набегание монет)
  сделаны одним `requestAnimationFrame`-циклом — так проще держать их вместе.
- Полёты «в цель» считают координаты на лету (`getBoundingClientRect`), поэтому
  цель (счётчик, таб) должна быть на экране в момент старта.
- Анимации матча на anime.js v4 (`js/vendor/anime.umd.min.js`) — можно оставить
  библиотеку или переписать на WAAPI с теми же значениями.
