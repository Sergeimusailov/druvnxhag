# Арена Карт — документация проекта

## 1. Общее описание

**Арена Карт** — прототип мобильной браузерной карточной игры в жанре Triple Triad:
два игрока по очереди выкладывают карты на поле 3×3 и захватывают карты соперника,
сравнивая числа на соприкасающихся сторонах. Побеждает тот, кто занял больше клеток.

**Технологии:** чистые HTML / CSS / JavaScript. Без фреймворков, без сборки, без
зависимостей из npm. Единственная внешняя библиотека — [anime.js](https://animejs.com)
v4.5.0 (UMD-сборка), положенная локально в `js/vendor/`.

**Хостинг:** статика на GitHub Pages. Любой файл открывается напрямую в браузере,
никакой серверной части нет.

**Платформа:** вёрстка рассчитана на мобильный экран (контейнер `max-width: 430px`,
вертикальная компоновка). Работает и на десктопе. Drag-and-drop реализован на
Pointer Events, поэтому одинаково работает мышью и пальцем.

**Данные пользователя:** сохранённая колода лежит в `localStorage`
(ключ `arena-cards-deck-v1`), это единственное персистентное состояние.

**Язык интерфейса:** русский.

### Ключевые модули

**`js/cards.js`** — общий для матча, онбординга и коллекции.
- `CARD_ROSTER` — массив из 48 карт `{ name, top, left, right, bottom, pic }`.
- `CARD_PIC_POOL` — 9 картинок; карте без явной `pic` при загрузке достаётся случайная.
- `shuffle(arr)`, `drawPlayerSet()` — случайные 8 карт из ростера.
- `DECK_SIZE = 8`, `DECK_STORAGE_KEY = 'arena-cards-deck-v1'`.
- `getSavedDeckNames()` / `saveDeckNames()` / `getSavedDeckCards()` — работа с localStorage.
- `drawSavedPlayerSet()` — сохранённая колода в перемешанном виде, иначе случайная.
- `CARD_MASK_FRAME_PATH`, `CARD_MASK_BEVEL_PATH` — SVG-пути рамки карты.
- `cardInnerHTML(card)` — разметка карточки: картинка + SVG-рамка + 4 числа.

**`js/match.js`** — движок партии: состояние, правила захвата, рендер, таймер,
анимации, ИИ соперника, drag-and-drop.

**`js/onboarding.js`** — содержит **копию** движка матча плюс надстройку обучения
(шаги, тултипы, спотлайт, ограничение драга). Движок продублирован намеренно:
проект без сборщика, а обучению нужно вклиниваться в ход партии. **Важно: правки
в игровой логике нужно вносить в оба файла.**

### Визуальная система карты

Карта — это `div.card` с содержимым из `cardInnerHTML()`:
1. `<img class="card-pic">` — картинка на всю площадь;
2. `<svg class="card-mask">` — рамка, залитая `fill="currentColor"`;
3. четыре `<span class="num">` — числа сторон.

Цвет рамки задаётся CSS-свойством `color` у `.card`, поэтому перекрашивание карты
при захвате — это смена класса владельца:

| Класс | Цвет | Смысл |
|---|---|---|
| `.card` | `#252525` | нейтральная |
| `.card.owner-you` | `#2265d3` | карта игрока |
| `.card.owner-opp` | `#e32d2d` | карта соперника |
| `.card.in-hand` | `#252525` | карта в руке |
| `.card.face-back` | паттерн `beckcard.svg` | рубашкой вверх |

На каждой странице, использующей `cardInnerHTML()`, должен быть один общий
`<mask id="card-mask-def">` в скрытом `<svg>` в начале `<body>`.

## 3. Логика игры

### Поле и карта

Поле — 9 клеток, индексы 0–8 слева направо, сверху вниз:

```
0 1 2
3 4 5
6 7 8
```

У карты четыре числа — сила сторон: `top`, `left`, `right`, `bottom`
(в текущем ростере значения 0–9).

### Ход партии

1. Каждому игроку раздаётся набор из 8 карт: 3 в руку, 5 в колоду.
   Игрок получает **сохранённую в коллекции колоду** (`drawSavedPlayerSet()`),
   соперник — случайные 8 карт из ростера.
2. Первым ходит игрок. На ход даётся **20 секунд**.
3. Игрок перетаскивает карту из руки в свободную клетку → разрешаются захваты.
4. Показывается плашка «Ход соперника», ходит ИИ.
5. Перед ходом игрока рука добирается из колоды до 3 карт.
6. Когда заполнены все 9 клеток — матч заканчивается.

Если время истекло, `onYourTimeout()` автоматически ставит случайную карту из руки
в случайную свободную клетку.

Итог: `Победа!` / `Поражение` / `Ничья` по числу занятых клеток.

### Правило захвата

При постановке карты проверяются все четыре соседние клетки. Карта соперника
захватывается, если число нашей карты на соприкасающейся стороне **строго больше**
числа соседа на его встречной стороне:

| Направление | Сравнение |
|---|---|
| сосед сверху | наш `top` > его `bottom` |
| сосед снизу | наш `bottom` > его `top` |
| сосед слева | наш `left` > его `right` |
| сосед справа | наш `right` > его `left` |

Захватов за один ход может быть несколько — по одному в каждом направлении
(**мультизахват**).

### Прострел (цепной захват)

После успешного прямого захвата проверяется **следующая клетка на той же прямой**.
Если там стоит ещё одна карта соперника, сравниваются дальняя сторона захваченной
карты и встречная сторона следующей — и при победе она тоже захватывается.

Прострел работает **только по одной линии** (вертикальной или горизонтальной) и
только на один шаг, поэтому на поле 3×3 он даёт максимум одну дополнительную карту
на направление.

Пример: карта ставится в клетку 2, бьёт вниз карту в клетке 5, и её нижнее число
пробивает карту в клетке 8 — обе клетки переходят игроку одним ходом.

### Реализация в коде

`capturesForPlacement(board, index, card, owner)` возвращает массив событий:

```js
{ index,          // какая клетка захвачена
  dir,            // 'up' | 'down' | 'left' | 'right' — направление атаки
  chain,          // false — прямой захват, true — прострел
  attackerIndex } // с какой клетки шла атака
```

Далее захват разрешается в два этапа:
- `commitPlacement()` — ставит карту, убирает её из руки, обновляет счёт и рендер,
  но **владельцев захваченных карт ещё не меняет**, а возвращает список событий;
- `resolveCaptures()` — проигрывает анимацию (подсветка чисел → перекрас) и только
  после неё фиксирует смену владельцев и пересчитывает счёт.

### ИИ соперника

`chooseOpponentMove()` — жадный перебор: все карты руки × все свободные клетки,
выбирается вариант с максимальным числом захватов (прострелы учитываются
автоматически, так как считаются из того же массива событий). При равенстве
вариантов выбор слегка рандомизируется, чтобы ИИ не был предсказуемым.
Перед ходом ИИ «думает» 3–6 секунд, показывая статус.

### Коллекция и колода

- Ростер — 48 карт, колода — ровно 8 карт.
- Тап по карте открывает bottom sheet с действием «Добавить» / «Удалить».
- Кнопка «Сохранить» появляется, только когда колода полная (8 карт) **и** отличается
  от сохранённой.
- Сохранение пишет имена карт в `localStorage`, матч читает их при старте.

### Онбординг

Обучение — это **тот же матч с зафиксированным сценарием**: конкретные карты в руках
обеих сторон и заранее просчитанные ходы, чтобы подсказки всегда совпадали с тем, что
на экране.

Сценарий описан массивом `STEPS` (14 шагов). Виды шагов:

| `kind` | Что делает |
|---|---|
| `info` | Тултип с кнопкой «Продолжить», подсветка элемента |
| `drag` | Ждёт реального перетаскивания игроком; чужие карты и клетки заблокированы |
| `auto-opp-move` | Скриптовый ход соперника заранее заданной картой |
| `final` | Финальный тултип с кнопкой «Начать игру» |

Полезные поля шага: `target` / `targets` (что подсветить), `compare` (какие числа
подсветить — на поле или **в руке**), `tooltipAbove` (принудительно показать тултип
над целью), `avoidIndexes` (расширить область привязки тултипа, чтобы он не перекрыл
важные карты).

Чему учит сценарий: первый ход → одиночный захват → двойной захват соперника
(мультизахват показывается самой анимацией) → прострел, которым игрок возвращает
обе клетки.

После финального шага `finishScript()` выключает режим сценария (`scriptMode = false`),
и партия продолжается как обычный матч: настоящий ИИ, таймер, добор карт.

## 4. Анимации: действие → анимация

Все JS-анимации построены на anime.js 4.5.0. Ниже — полный перечень в формате
«действие → что происходит».

### API anime.js v4 (кратко)

Библиотека подключается обычным `<script src="js/vendor/anime.umd.min.js">`.
Глобальная переменная `anime` в v4 — это **объект-неймспейс, а не функция**:

```js
anime.animate(target, {
  opacity: [0, 1],
  duration: 400,
  ease: 'outQuad',
  onUpdate: () => {},
  onComplete: () => {},
});
```

Правила, которые важно помнить при правках:
- цель передаётся **первым аргументом**, а не полем `targets`;
- параметр называется `ease`, а не `easing`;
- колбэки — `onComplete` / `onUpdate` (не `complete` / `update`);
- имена easing — без префикса `ease`: `outQuad`, `inQuad`, `inOutQuad`,
  `outElastic(1, 0.6)`; `linear` и `cubicBezier(...)` пишутся как раньше;
- целью может быть обычный JS-объект (`{ p: 100 }`) — так сделаны таймер,
  перекрас при захвате и подсказка драга;
- `anime.animate()` возвращает инстанс с `.pause()` — используется в `stopTimer()`.

### Матч и онбординг

| Действие | Анимация | Реализация |
|---|---|---|
| Карта приземлилась на поле | Squash-bounce: карта возникает из масштаба 0.5 и упруго «плюхается» с проскоком | `playLandAnimation()`, 420 мс, `outElastic(1, 0.6)` |
| Карта заняла клетку | Всплеск из 10 частиц по кругу, цвет владельца, с угасанием | `spawnParticles()`, 500 мс, `outQuad` |
| **Карта захвачена: шаг 1** | Подсвечиваются **обе сравниваемые цифры** — жёлтый круг с пульсацией размера | `highlightCaptureNumbers()` + CSS `numCaptureHl`, 900 мс |
| **Карта захвачена: шаг 2** | Направленный перекрас: цвет нового владельца «заливает» карту от той грани, откуда пришла атака (clip-path вайп) | `sweepRecolor()`, 900 мс, `cubicBezier(0.55,0.06,0.68,0.19)` — медленный старт, ускорение к концу |
| Мультизахват (2–3 карты) | Все подсветки показываются разом, затем все перекрасы идут **параллельно**, каждый в свою сторону | `resolveCaptures()` |
| Прострел | Внутри линии перекрасы идут **последовательно**: сначала ближняя карта, затем дальняя — цвет визуально «бежит» по линии | `resolveCaptures()`, ветка `chain` |
| Соперник берёт карту из колоды | Рубашка вылетает от бейджа колоды к клетке, реально изменяя `left/top/width/height` | `flyGhost()` / `flyFromDeckToCell()`, 900 мс, `cubicBezier(.32,.72,.35,1)` |
| Карта соперника раскрывается | Двухфазный флип: `scaleX` 1→0, подмена содержимого, 0→1 | `flipCardToFront()`, 150 + 150 мс |
| Добор карты в руку | Рубашка летит от бейджа колоды в слот руки, затем переворачивается лицом | `refillYourHandWithFlight()` |
| Смена хода | Затемняющая плашка «Ваш ход» / «Ход соперника»: проявление, пауза 3 с, угасание | `showTurnOverlay()`, 250 мс на вход и выход |
| Идёт ход соперника | Рука тускнеет до `opacity: 0.4` и перестаёт принимать нажатия | CSS `.hand.disabled`, 0.2 с |
| Соперник «думает» | Появляется статус с бегущими точками, текст циклически меняется каждые 1.3 с | CSS `dotPulse` 1.4 с + `startOppThinkingStatus()` |
| Тикает таймер хода | Зелёная дуга-гейдж укорачивается за 20 с; на 40% остатка желтеет, на 15% краснеет | `startTimer()`, линейно + CSS `transition: stroke 0.3s` |
| Перетаскивание карты | Клон карты следует за пальцем, оригинал становится полупрозрачным | `makeDraggable()` + CSS `.dragging` |
| Наведение на клетку при драге | Клетка подсвечивается синей рамкой и заливкой | CSS `.cell.drag-over` |
| Матч завершён (Победа/Поражение) | Подсчёт карт (затемнение проигравшего → подсветка победителя), затем экран результата — подробности в разделе ниже | `endGame()` → `playCountingAnimation()` + `showResultScreen()` |
| Матч завершён (Ничья) | Численно недостижимо на 3×3 (9 клеток — нечётное число), но на случай ручной подмены счёта в коде есть запасной вариант: старая текстовая плашка без анимации подсчёта | `endGame()`, ветка `scoreYou === scoreOpp`, 400 мс, `outQuad` |

### Только онбординг

### Подсчёт карт и экран результата (конец матча)

По окончании партии (`endGame()` в `js/match.js` и `js/onboarding.js`) вместо
старой текстовой плашки проигрывается анимация подсчёта карт, а затем — полноэкранный
экран результата. Стили и разметка (`.mr-*` классы) вынесены в `css/match-result.css`,
подключённый теперь и в `match.html`/`onboarding.html`, а не только в демо-стенде.

| Шаг | Анимация | Реализация |
|---|---|---|
| 1. Затемнение проигравшего | Карты проигравшей стороны темнеют через `filter: brightness/saturate` (не `opacity` — иначе рамка и картинка теряются на тёмном фоне) | `dimLoserCards()` + CSS `.mr-dim`, 400 мс (`RESULT_DIM_MS`) |
| 2. Подсветка победителя | После того как затемнение отыграло, карты победителя разом получают короткий импульс цветной тени позади карточки (цвет — как у `owner-you`/`owner-opp`) | `glowWinnerCards()` + CSS `.mr-glow` / `@keyframes mrGlow`, 700 мс (`RESULT_GLOW_MS`), box-shadow blur/spread 15px/6px |
| 3. Экран результата | После паузы 400 мс (`RESULT_AFTER_COUNT_PAUSE_MS`) поверх поля проявляется оверлей: заголовок/подзаголовок под исход, награда (статичное число — экономика ещё не подключена), для победы — дополнительно 2 карты-награды | `showResultScreen()` + CSS `.mr-result-overlay.visible` |

Шаги 1 и 2 идут **последовательно**, а не одновременно: сначала должно отыграть
затемнение проигравшего, и только потом стартует подсветка победителя — это
специально разнесено через `await wait(RESULT_DIM_MS)` между `dimLoserCards()` и
`glowWinnerCards()`.

По клику «Забрать» (`#mrClaimBtn`) — переход на `index.html`.

Черновые числа наград (170 за победу / 30 за поражение) и тексты — заглушки,
экономика не реализована. Правки нужно вносить в оба файла — `js/match.js` и
`js/onboarding.js` (движок продублирован, см. начало раздела 2).

Изолированно эту анимацию (без розыгрыша партии) можно посмотреть на
`match-result.html` — демо-стенде с теми же двумя исходами и кнопками
«Победа»/«Поражение», кнопки под неё не выведены на главный экран.

Макеты — Figma 15984:55879 (шторка — 15969:54523). Точка входа — фиолетовый

ивента поверх таб-бара (въезжает справа, крестик возвращает на главную).
Сверху — фиолетовая шапка: бейдж «До 1 января», «Делим 10 000 000 ₽»,
описание, компактный сегмент-контрол «Задания» / «Награды»
(`.v2-segmented-compact`), справа кнопка «i». На «Заданиях» фиолетовый весь
фон, на «Наградах» — только шапка с «клювом» вниз к молнии трека
(`assets/v2-event-head.svg`, кончик выставляется в `placeHeadV()`); фон
переливается при смене вкладки.

- **Шторка с описанием** выезжает снизу при первом входе (флаг
  `v2.eventIntroSeen` в localStorage); закрывается крестиком или «К заданиям»,

  в макете плейсхолдер.
- **Задания** — те же карточки, что в разделе «Задания» (`taskHTML()`), с
  подписью прогресса «Ещё N …» и наградой «+1». Каждое задание

  (серая рамка и ромб). Пройденная часть трека, ромбы и перемычки — сиреневые, сама полоска — фиолетовая, как шапка.
  Пока есть что забрать, на вкладке «Награды» горит красная точка.

| Действие | Анимация | Реализация |
|---|---|---|
| «Забрать» в задании ивента | Из плитки награды вылетают молнии и по дугам летят во вкладку «Награды»; вкладка подпрыгивает, искры; задание уезжает в «Выполненные», трек сдвигается, на «Наградах» «впрыгивает» красная точка | `claimEventTask()` → `flyBolt()`, `burstAt()`, `collapse()` / `expandIn()` из `js/tasks.js` |
| Вход на «Награды» после полученных очков | Полоска трека (того же фиолетового, что шапка, растёт из кончика «клюва») едет от последнего показанного уровня к новому; каждая награда по пути «включается»: короткий скейл, подсветка шестигранника, ромб подпрыгивает, появляется «Забрать» | `animateTrackProgress()`; трек рисуется по `EVENT.shown`, очки — `EVENT.points` |
| «Забрать» на треке наград | Карточка «приседает», открывается тот же экран подарка, что в «Заданиях»; после «Забрать» — снова трек, у награды галочка | `claimEventReward()` → `openGiftOverlay()` |

Слой эффектов `#v2FxLayer` лежит выше экрана ивента (z-index 38) и ниже
экрана подарка (40), чтобы молнии летели поверх ивента.

Данные — объект `EVENT` в `js/event.js`, в памяти (после перезагрузки демо
начинается заново).

Верхняя навигация каждого раздела (кнопка слева, заголовок, кнопка справа)
закреплена (`position: sticky`) — контент скроллится под ней. Как только
экран прокручен, под шапкой плавно появляется system-scroll-edge-effect:
блюр фона 10px, сходящий на нет книзу (маска-градиент), и лёгкое
затемнение (`.v2-screen.is-scrolled > .v2-appbar::before`).

Фон v2 — один фиксированный слой на весь вьюпорт (`.v2-bg-fixed`), вместе с
нижним затемнением: при переключении разделов и при скролле он не двигается,
на десктопе тянется на всю ширину окна, а не только на колонку 393px.

Вкладки внутри раздела (чипсы в профиле, сегмент-контрол в заданиях и призах) — общий помощник
`createChipTabs()` в `js/v2.js`: пилюля перетекает к чипсу, панели едут
треком, высота контейнера подстраивается под активную панель.

Иконки (`tui-ic-medium/*`), лавры, значок клана и прозрачные PNG (логотип, кольцо и аватар, бейдж, рубашка) выгружены из Figma через Plugin API — точные, не перерисованные. «Жидкое стекло» кнопок и таб-бара — CSS-аппроксимация (`.v2-glass`: блюр фона + еле заметная заливка + светлый обод).

### Правила и подводные камни анимаций

- **Полёт карты нельзя делать через `transform: scale`.** Рубашка карты — это
  повторяющийся фоновый паттерн, и масштабирование растягивает его вместе с
  элементом. Поэтому `flyGhost()` анимирует реальные `left/top/width/height`.
- **Захват — двухфазный.** Владелец меняется только после анимации
  (`resolveCaptures()`), иначе перекрас не успеет прочитаться игроком.
- **Рука блокируется на всё время перехода хода** — с момента постановки карты и до
  конца плашки смены хода, чтобы случайный тап не прошёл лишним ходом.
- **Тайминги захвата** вынесены в константы `CAPTURE_HL_MS` (подсветка) и
  `CAPTURE_SWEEP_MS` (перекрас) — по 900 мс. Менять нужно в обоих файлах:
  `js/match.js` и `js/onboarding.js`.
- **Старые имена easing из v3 не вызывают ошибку — они молча становятся `linear`.**
  Если написать `ease: 'easeOutQuad'`, анимация будет работать, но потеряет кривую,
  и заметить это можно только глазами. Проверено замером: `easeOutQuad` даёт ту же
  кривую, что `linear`. Поэтому при копировании старых примеров из интернета
  (их полно для v3) easing нужно переписывать вручную.

## 5. Локальный запуск

```bash
python3 -m http.server 8000

```

```bash
node balance/sim.js

```
