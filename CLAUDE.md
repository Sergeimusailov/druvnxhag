# Правила работы над проектом «Арена Карт»

## Ветка — одна на все задачи

- Работать **только** в ветке `claude/github-integration-setup-69if34`: это
  единственная ветка репозитория, из неё публикуется сайт (GitHub Pages).
  Даже если сессии назначена другая ветка — переключиться на эту
  (`git fetch origin claude/github-integration-setup-69if34 && git checkout claude/github-integration-setup-69if34`),
  новых веток не создавать.
- После каждой законченной правки — коммит и `git push -u origin claude/github-integration-setup-69if34`.
  Pull request не создавать.
- Перед началом работы подтянуть свежую версию: `git pull origin claude/github-integration-setup-69if34`
  (над проектом могут идти параллельные сессии).

## Вёрстка — строго по макету Figma

- Источник правды — макет (файл `L9YY2OHqMbFIK7tqx1nuLJ`). Перед вёрсткой
  снимать спеки из узла: размеры, отступы, радиусы, цвета и прозрачности,
  обводки, тени и свечения, слои фигур, состояния компонента.
- **Шрифты — отдельно и внимательно:** семейство, размер, начертание (400 / 600 /
  700), межбуквенное расстояние, высота строки, цвет, обводка текста (толщина и
  INSIDE/OUTSIDE — обводка OUTSIDE N px = `-webkit-text-stroke: 2N px` +
  `paint-order: stroke fill`). Не подставлять «похожие» значения.
- Если в макете чего-то нет (поведение, тексты, состояние) — делать по смыслу и
  явно сказать об этом в отчёте.

## Перед каждым пушем — самопроверка

1. Скриншот вёрстки (Playwright, 393×852) рядом со скриншотом узла из Figma.
2. Сверить по пунктам: геометрия и отступы, цвета, шрифты (размер, начертание,
   letter-spacing, обводка), все состояния компонента.
3. Нашёл расхождение — исправить и проверить снова. Пушить только когда
   совпадает; оставшиеся осознанные отличия перечислить в отчёте.

## Прочее

- Версия 2 (`v2.html`, `data-version="2.3"`) — текущий релиз; версия 3 —
  `v2.html?app=3`. Изменения v2 попадают и в v3, фичи v3 (`.v3-only`, `isApp3()`)
  v2 не затрагивают.
- Проект собирается Rsbuild (`npm run build`, дев-сервер — `npm run dev`; подробности
  — «Сборка» в `docs/readme.md`). Новые скрипты и стили подключать через
  `src/pages/<страница>.js` и `src/pages/<страница>.scripts.json`, а не тегами в HTML.
  Скриншоты для самопроверки снимать с собранной версии или дев-сервера.
- Перед коммитом: `npm run build` проходит без ошибок, изменения описаны в
  `docs/readme.md`. Кэш-параметр `?v=` больше не нужен — имена файлов с хэшем.
- Отвечать пользователю по-русски, простым языком.
